# 截图与录屏清单

> **状态：已完成。** 实际产出见 `docs/images/01~07-*.png`（每张旁边有同名 `.layout.txt`，
> 是当时的 UI 文本快照，可逐条核对画面内容）与 `docs/demo.mp4`。
> 拍摄环境：DevEco 自带 HarmonyOS 5.0.5 模拟器，1260×2720，开发版镜像（允许安装未签名 HAP）。
> 本文件保留为复现脚本：换真机时按同样步骤重拍即可。

## 0. 准备

1. 把工程复制到**纯英文路径**（例如 `D:\HarmonyProjects\SmartDormLink`）——hvigor 不支持中文路径。
2. DevEco Studio 打开 → 等待 Sync → `Project Structure → Signing Configs` 勾选自动签名（需登录华为账号）。
3. 启动模拟器（Device Manager 创建；需开启 Hyper-V/WHPX）或连接真机，点击 Run ▶。
4. 建议手机分辨率 1080×2340 左右；系统语言中文；保持默认浅色主题。
5. 首次进入后**先不要**点「恢复出厂」，以保证看到 6 条内置规则。

保存位置：全部放到工程 `docs/images/` 下，命名为下表「文件名」列。

## 1. 驾驶舱总览 —— `01-dashboard.png`

- 进入：启动 App，停留在「驾驶舱」Tab。
- 操作：无。
- 预期：顶部「本地数据已就绪（Preferences + RDB）」；环境模拟区 3 个滑块（温度 26.5°C / 湿度 62% / 光照 300lux）；
  设备状态区 4 张卡片（书桌灯、循环扇、加湿器、遮光帘），底部 4 个 Tab。
- 用途：README 首图；报告 6.1 运行效果。

## 2. 规则列表 —— `02-rules.png`

- 进入：底部点「规则」Tab。
- 预期：`5 条启用 / 共 6 条（上限 12 条）`；6 张规则卡带优先级徽标（P9/P8/P7/P6/P5/P3）、条件文案、动作文案、启停开关。
- 用途：报告 3.1 功能设计 / 6.1。

## 3. 规则编辑与校验拦截 —— `03-rule-editor.png`

- 进入：规则 Tab → 右上「新建」。
- 操作：名称留空，把「优先级」拖到 10，条件阈值拖到越界位置（或直接把湿度阈值拖到 101 不可达时改用名称留空）。
- 点「创建规则」。
- 预期：页面底部出现红色「校验未通过」区块，列出「规则名称不能为空」等具体提示，且不返回上一页。
- 用途：报告 5.3 问题与修复 / 目标三「数据持久化与异常处理」证据。

## 4. 场景演练结果 —— `04-scenario-result.png`

- 进入：「场景」Tab → 点「梅雨午后」卡片上的「一键演练」。
- 预期：Toast「已套用「梅雨午后」并完成演练」；卡片右上出现「上次演练」标记；
  回到「驾驶舱」应看到环境变为 31.5°C / 88% / 900lux，风扇、加湿器、窗帘按规则开启；
  结果卡显示「命中 N 条规则，设备已联动」及冲突裁决文案（若有）。
- 用途：报告 6.1；证明「规则引擎按实际输入计算」+「冲突优先」。

## 5. 执行日志（顺序 + 冲突） —— `05-logs.png`

- 进入：「日志」Tab。
- 预期：倒序列出刚才的记录；每条含 `#序号`、规则名、`P优先级`、时间、`条件 …`、`变化 A → B`；
  被丢弃的动作显示红色「冲突 … 被「某规则」优先占用」。
- 用途：报告 5.2 测试结果 / 6.1；证明「记录触发条件、设备变化和执行顺序」。

## 6. 重启恢复对比 —— `06-restore-before.png` / `07-restore-after.png`

1. 在驾驶舱把温度拖到 33°C、湿度拖到 85%，执行一次联动（加湿器/风扇应开）。
2. 截第 1 张：`06-restore-before.png`（记录当时的设备卡片与日志条数）。
3. **从最近任务里把 App 划掉（杀进程）**，或执行 `hdc shell aa force-stop com.zhaoshuo.dormlink`。
4. 重新点图标启动，等界面加载完。
5. 截第 2 张：`07-restore-after.png`。环境值、设备开关与档位、规则启停状态、日志条数应与第 1 张一致。
- 用途：报告 6.2 数据恢复与集成 —— 这是「持久化」这一评分点的核心证据。

## 8. 录屏 —— `docs/demo.mp4`（1 分 12 秒，30 fps）

产物已在仓库中：`docs/demo.mp4`，630×1360、H.264、30 fps、2157 帧、1.86 MB。

**录制方式（模拟器镜像没有 screenrecord）**：在设备端用 4 路并发 `snapshot_display` 连拍得到
35.8 fps 的连续画面（2573 帧，文件名内嵌毫秒时间戳），重采样到 30 fps 后用 ffmpeg 编码；
交互全部由 `uitest` 注入，不是先摆好页面再逐张拼接。

| 时间 | 操作 | 画面应出现 |
| --- | --- | --- |
| 0-15s | 启动 App，停在驾驶舱 | 存储就绪横幅、3 条滑块、4 张设备卡 |
| 15-21s | 拖温度、湿度滑块 | 数值跟随变化 |
| 21-24s | 点「执行一次联动」 | 设备卡开关自动变化、结果提示 |
| 24-27s | 手动拖书桌灯亮度 | 亮度档位跟随 |
| 27-34s | 切「场景」→ 一键演练「深夜自习」 | 环境值整体套用，提示命中规则 |
| 34-42s | 切「规则」→ 新建 → 直接保存 | 红色校验提示拦截 |
| 42-50s | 切「日志」 | 带序号/条件/变化/冲突的记录（顺序与裁决） |
| 50-72s | 杀进程 → 重新打开 | 环境/设备/规则/日志与关闭前一致 |

复现与自检：

```powershell
python tools/dev/record_real.py    # 重新录制（需要模拟器在线）
python tools/dev/verify_video.py   # 抽帧统计变化 + 与设备实时截图比对
```

驱动过程日志在 `docs/evidence/recording-driver-log.txt`（含每次点击坐标与界面文本回读）。
